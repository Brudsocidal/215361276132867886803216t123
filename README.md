# VN DELAY — PySide6 + QML + Flask (phase 1 scaffold)

This rebuild follows the supplied prompt's architecture. The previous PyWebView client is not reused as the UI host.

## What is included
- PySide6/QML client with login, game library, module placeholder, admin panel and broadcast overlay scaffold.
- Flask API with login, version, broadcast and game-status endpoints.
- GTA/FiveM, Valorant and Roblox hook modules. `run_optimization()` and `stop_optimization()` are intentionally `pass`.
- PyInstaller spec includes QML/assets and certifi.
- Windows build script and basic server tests.

## Important limitations
- This is a scaffold, not a production-ready authentication service. The JSON files are suitable only for a small test deployment; use persistent storage and stronger session/token management before public release.
- Module UI is shown inside the launcher window; the optimization modules are Python hooks, not separate EXEs. Building separate EXEs and truly embedding their native windows is a separate decision/test. The current scaffold avoids claiming that native EXE embedding is complete.
- Flag shader is marked as a test/fallback area. No real 3D shader is claimed as verified; provide a flag texture/GIF and test on the target GPU/Qt version.
- Auto-update is scaffolded as a safe placeholder; do not use self-updating in production until download/signature/checksum and rollback behavior have been tested.
- Set `VNDELAY_SECRET_KEY` and `VNDELAY_ADMIN_PASSWORD_HASH`/whitelist values before deployment. Never use the sample credentials on a public server.

## Run the client (Windows)
```bat
cd client
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py
```
Client API base URL defaults to `http://127.0.0.1:5000`. Set `VNDELAY_API_URL` to your deployed HTTPS API URL.

## Run the server locally
```bat
cd server
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python app.py
```
Open `http://127.0.0.1:5000/api/health`.

## Whitelist setup
Edit `server/whitelist.json`. `password_hash` is a PBKDF2-SHA256 string generated by `server/create_user.py`; do not store plaintext passwords. Example:
```bat
python create_user.py demo_user "replace-with-a-long-password" user
```
The script prints a JSON record; copy it into `whitelist.json`. For an admin, use role `admin`. Keep secrets out of source control.

## Render deployment
1. Push the `server/` directory to a GitHub repository (or set the Render root directory to `server`).
2. Create a Render Web Service, choose the repository, root directory `server`, build command `pip install -r requirements.txt`, start command `gunicorn app:app`.
3. Configure `VNDELAY_SECRET_KEY` as a long random secret in Render environment variables.
4. JSON files on a free/ephemeral filesystem may reset on redeploy/restart. For real use, migrate whitelist/game/version/broadcast storage to a persistent database or durable disk. Do not store EXE assets on Render; use GitHub Releases and store only its URL in `version.json`.
5. Set the client `VNDELAY_API_URL` to the Render HTTPS URL.
6. Smoke-test `/api/health`, `/api/version`, `/api/game/gta/status`, and login before distributing any client.

## Build EXE
Run `client\Build_Exe.bat` on Windows with Python 3.10–3.12:
```bat
cd client
Build_Exe.bat
```
Output is `client\dist\VNDELAY\VNDELAY.exe` plus its support files. This is intentionally `onedir` first for easier QML diagnosis. Do not distribute only the EXE from an `onedir` build. Switch to `onefile` only after QML plugins and runtime resources have been tested on a clean Windows machine.

## GitHub Releases update workflow
1. Build and test a version on a clean Windows machine.
2. Upload the tested launcher artifact to a GitHub Release with a version tag.
3. Calculate SHA-256 (`certutil -hashfile VNDELAY.exe SHA256`).
4. As admin, update `version.json` through the API/Admin Panel with the HTTPS release asset URL and checksum.
5. Test update on a disposable install first. The automatic replacement flow is intentionally not enabled in this scaffold.

## Images / flag
Replace `client/assets/bg_vietnam.jpg`, `flag_vn_texture.png`, `flag_vn_wave.gif`, and the game banner files with your own assets. `Flag3D.qml` currently uses an animated GIF fallback when supplied; shader behavior needs testing against the installed Qt Quick version/GPU.

## Module integration decision
The current app calls the Python module hook in-process and displays a QML module view in the same launcher window. If you later build each module as an EXE, native-window embedding via QProcess is platform-sensitive and must be tested; a separate process window is the fallback. Do not assume a QML `Loader` can load another process's UI.
